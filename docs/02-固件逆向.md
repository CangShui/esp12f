# 02 · 固件逆向方式

> 目标：说明**在没有源码的情况下，如何从一颗 1MB 的 flash dump 反推出全部硬件行为**，
> 并且每一步都可复现。所有工具都在 [`tools/reverse/`](../tools/reverse/) 里。

---

## 0. 结论先行

逆向最终产出的是这几条**可直接写进代码的事实**：

| 事实 | 值 | 来源 |
|---|---|---|
| 电源键引脚 | GPIO12 | `digitalWrite(12,1)` 前后的立即数 |
| 开机时序 | 高 500ms → 低 | `0x40203BB2` 处 `movi.n a3,500` |
| 关机时序 | 高 8000ms → 低，静置 2000ms | `0x40203BF1` 处 `movi.n a3,8000` |
| 复位键引脚 | GPIO5 | `digitalWrite(5,1)` |
| 状态引脚 | GPIO14（高=开机） | `digitalRead(14)` + 真机实测 |
| 配网按钮 | GPIO4（低=按下） | function A 首条 `digitalRead(4)` + `"Wait for Webconfig"` 字符串 |
| 配置存储 | flash `0xFB000` | 链接脚本 `_EEPROM_start = 0x402fb000` |

## 2. 第一步：拿到 dump

```powershell
# 备份（若还没有）
python ..\flash.ps1 -Mode Backup -Port COM3 -OutDir ..\..\backup
```

dump 到手后先看结构：

```powershell
python -m esptool image-info ..\..\backup\es12f_firmware_backup_1MB.bin
```

原厂 1MB dump 的布局（本项目实测）：

| Flash 偏移 | 内容 |
|---|---|
| `0x00000` | eboot 引导程序（`E9 01 03 20 5C F4 10 40`，nseg=1，entry `0x4010F45C`） |
| `0x01000` | 应用镜像（`E9 05 03 20 B8 00 10 40`，nseg=5，entry `0x401000B8`） |
| `0x50C10` | 应用结束，之后到 `0xFB000` 是 `0xFF` |
| `0xFB000` | EEPROM：SSID@`0x00`、密码@`0x20`、AccessKey@`0x60`、标志位@`0x75/0x76` |
| `0xFC000` | RF 校准（`rfcal_addr=0xFC000`） |
| `0xFD000` | SDK system param |
| `0xFE000` | SDK system param 副本 |

**关键点：`0xFB000` 与 Arduino core 的 `eagle.flash.1m.ld` 里
`_EEPROM_start = 0x402fb000` 完全一致。** 这就是为什么新固件能直接读到原厂已配好的 WiFi。

验证：

```powershell
Select-String -Path toolchain\arduino\packages\esp8266\hardware\esp8266\3.1.2\tools\sdk\ld\eagle.flash.1m.ld -Pattern '_EEPROM_start'
# PROVIDE ( _EEPROM_start = 0x402fb000 );
```

## 3. 第二步：定位"应用入口"和"字符串"

### 3.1 解析镜像头，拿到段表

```python
import struct
d = open('backup/es12f_firmware_backup_1MB.bin','rb').read()
base = 0x1000                       # 应用镜像在 flash 0x1000
magic, nseg, mode, sf = struct.unpack_from('<BBBB', d, base)
entry = struct.unpack_from('<I', d, base+4)[0]
print('nseg=%d mode=%d freq=0x%02X entry=0x%08X' % (nseg, mode, sf, entry))
p = base + 8
for i in range(nseg):
    a, s = struct.unpack_from('<II', d, p)
    print('  seg%d addr=0x%08X size=%d file=0x%X..0x%X' % (i, a, s, p+8, p+8+s))
    p += 8 + s
```

本项目实测输出：

```
nseg=5 mode=3 freq=0x20 entry=0x401000B8
  seg0 addr=0x40201010 size=293848   ← irom0（代码，flash 映射）
  seg1 addr=0x40100000 size=316      ← IRAM
  seg2 addr=0x4010013C size=27176    ← IRAM
  seg3 addr=0x3FFE8000 size=1288     ← DRAM 初始化数据
  seg4 addr=0x3FFE8510 size=5888     ← DRAM（含 .rodata 字符串）
```

### 3.2 段地址 → 文件偏移的换算

反汇编时用到的地址是**内存地址**，要换算回文件偏移才能读字节：

| 内存段 | 文件偏移 |
|---|---|
| `0x40200000` 起（irom0，含 `0x40201010`） | `0x1000 + (addr - 0x40200000)` |
| `0x40100000` / `0x4010013C`（IRAM） | 按段表逐段算 |
| `0x3FFE8000` / `0x3FFE8510`（DRAM） | 按段表逐段算 |

`tools/reverse/xdis.py` 里的 `foff()` 已经把这套换算封装好了。

### 3.3 提取字符串，先看"这个固件想干什么"

```powershell
python tools\reverse\appstr.py ..\..\backup\es12f_firmware_backup_1MB.bin
```

原厂固件里最有价值的一批字符串（本项目实测）：

```
http://songguoyun.topwd.top/Esp_OTA_Update/wifiBootUp     ← 远程固件更新
http://songguoyun.topwd.top/Esp_updata_state.php?state=   ← 状态上报
/Esp_get_AccessKey.php?wifi_pass=                          ← 上传 WiFi 密码
mqtt.topwd.top                                             ← MQTT 服务器
Get Command / AutoBootUp                                   ← 云端控制指令
start dnsserver success./failed.                           ← 配网 DNS 服务器
WebServer started!                                         ← 配网 Web 服务
\r\nWait for Webconfig                                     ← 配网流程入口标志
error, not found ssid                                      ← 配网页表单校验
```

**`Wait for Webconfig` 这条字符串是本次逆向的关键突破口**——它把
"配网流程"这个函数和"GPIO4 按钮"联系了起来（见 §5）。

## 4. 第三步：反汇编（含一个必须知道的坑）

直接用 `objdump` 反汇编会有问题：**ESP8266 的镜像把代码段和数据段混在一起**，
objdump 按线性扫描会在数据区"漂移"，之后所有指令都错位。

本项目的做法是**自研 Xtensa 解码器**，逐条按真实长度前进：

```powershell
python tools\reverse\xdis.py ..\..\backup\es12f_firmware_backup_1MB.bin
```

`xdis.py` 里已经验证过的 Xtensa LX106 编码规律：

| 规律 | 说明 |
|---|---|
| 指令长度 | `(V & 0xF) >= 8` → 2 字节，否则 3 字节 |
| `ret.n` | 字面量 `0xF00D` |
| `movi.n` | op0 `0xC` 且 bit7=0；imm = `(V>>12)&0xF \| ((V>>4)&7)<<4`（7 位有符号） |
| `beqz.n` / `bnez.n` | op0 `0xC` 且 bit7=1；分支偏移在 `pc+4` |
| `l32i.n` / `s32i.n` | op0 `0x8` / `0x9` |
| `mov.n` | op0 `0xD` |
| `addi.n` / `add.n` | op0 `0xB` / `0xA` |
| `l32r` | op0 `0x1`，目标 = `((pc+3)&~3) - ((0x10000-imm16)<<2)` |
| `call0` / `j` | op0 `0x5` / `0x6`，`PC+4+s18*4`（call0）/ `PC+4+s18`（j） |

> 踩过的坑：op0 `0x2` 分组同时包含 RRI8 和 MOVI，光看 `t`/`s` 字段顺序会误判。
> 正确做法是用**比特位拟合**（把候选指令的编码规则算出来，看哪个能精确匹配 V），
> 并与 objdump 在**代码区**的输出交叉验证。

## 5. 第四步：从字符串反查调用者（本次的核心方法）

### 5.1 字符串地址怎么找

`l32r aN, <literal_slot>` 把字面量池里的 32 位值装进寄存器。
所以只要扫描**所有 `l32r` 指令**，把目标槽位的值读出来，就能建立
「哪个函数引用了哪条字符串」的映射。

```powershell
python tools\reverse\xl32r.py ..\..\backup\es12f_firmware_backup_1MB.bin
```

### 5.2 找到配网流程函数

`"\r\nWait for Webconfig"` 存在 `0x3FFE8853`。查它的字面量槽位：

```
0x402039E0 -> 0x3FFE8853  '\r\nWait for Webconfig'
```

再看**谁引用 `0x402039E0`** → 引用者就是配网函数。本项目定位到
**function A @ `0x402039EC`**。

### 5.3 反汇编 function A 的开头

```
402039EC: addi  a1, a1, -16
402039EF: movi.n a2, 4            ; pin = 4
402039FA: l32r  a0, digitalRead
402039FD: callx0 a0               ; a2 = digitalRead(4)
40203A00: mov.n a12, a2
40203A02: beqz.n a2, 0x40203A0A   ; if (GPIO4 == 0) → 走配网
40203A04: movi.n a2, -1
40203A06: j     0x40203A90        ; else return -1（跳过配网）
```

**结论确定：GPIO4 是配网按钮，低电平有效；"按住按钮上电 → 进配网"就是原厂行为。**

这条结论后来用真机验证过（`tools/monitor.py` 观察到按下按钮时 GPIO4 从 1 变 0）。

### 5.4 同理找出电源键/复位键/状态脚

`digitalWrite` / `digitalRead` 的函数地址从字面量池里读到：

```
digitalWrite = 0x40100334   （字面量槽 0x402039E8）
digitalRead  = 0x40100398   （字面量槽 0x4020172C）
pinMode      = 0x4020CDC0
delay        = 0x4020CD08
```

然后扫所有 `l32r a0, <digitalWrite>` + `callx0 a0` 的模式，
回看前一条 `movi.n a2, N` 拿到引脚号，看后一条 `movi.n a3, V` 拿到电平：

```
40203BB2: movi.n a2, 12       ; pin 12
40203BB5: movi.n a3, 1        ; HIGH
40203BB8: l32r   a0, digitalWrite
40203BBB: callx0 a0
40203BBD: movi.n a2, 500      ; delay(500)
...
40203BC5: movi.n a2, 12       ; digitalWrite(12, LOW)
```

→ **开机 = GPIO12 高 500ms 后拉低**。

```powershell
python tools\reverse\findgpio.py ..\..\backup\es12f_firmware_backup_1MB.bin
python tools\reverse\gpio.py      ..\..\backup\es12f_firmware_backup_1MB.bin
```

## 6. 第五步：读配置扇区

```powershell
python tools\reverse\dump_config.py ..\..\backup\es12f_firmware_backup_1MB.bin
```

原厂在 `0xFB000` 的布局（自定义结构，不是标准 SDK 格式）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| `0x00` | 32 | SSID |
| `0x20` | 64 | WiFi 密码 |
| `0x60` | 32 | AccessKey |
| `0x75` | 1 | `CheckStateEnable` |
| `0x76` | 1 | `LedEnable` |

新固件用 `firmware/ES12F_Local/storage.h` 读写同一扇区，因此**原厂已配好的 WiFi 直接可用**。

## 7. 第六步：把结论固化成代码

逆向结论最终落到 `firmware/ES12F_Local/config.h`：

```c
#define PIN_LED     2      // 指示灯（低电平点亮）
#define PIN_PWR     12     // 电源键
#define PIN_RST     5      // 复位键
#define PIN_STATE   14     // 电源状态（高 = 开机）
#define PIN_SENSE2  4      // 配网按钮（低 = 按下）

#define T_PWR_SHORT   500    // 开机：短按 500ms
#define T_PWR_LONG    8000   // 关机：长按 8000ms
#define T_PWR_SETTLE  2000   // 关机后静置 2000ms
#define T_RST_PULSE   200    // 复位脉冲 200ms
#define T_BOOT_SENSE  2000   // 上电等按钮的最长时间（原厂是无限等待）
```

## 8. 工具清单（`tools/reverse/`）

| 脚本 | 作用 |
|---|---|
| `xdis.py` | 自研 Xtensa 解码器（解决 objdump 漂移） |
| `findgpio.py` | 扫 `digitalWrite/digitalRead` 调用点，提取引脚号与电平 |
| `gpio.py` | 同上，输出更结构化的 GPIO 使用表 |
| `ctx.py` | 打印某个地址附近的上下文反汇编 |
| `xl32r.py` | 扫全部 `l32r`，建立「字面量槽 → 值/字符串」映射 |
| `xscan.py` | 通用线性扫描器 |
| `fit16.py` / `fit24.py` / `fitbr.py` | 编码拟合器（验证指令字段布局） |
| `appstr.py` | 提取应用段字符串并分类 |
| `mkelf.py` | 由 dump 重建可被 objdump 分析的 ELF |
| `sec_scan.py` / `sec_regions.py` / `sec_report.py` | 安全扫描（域名/URL/凭据） |
| `analyze_dump.py` | dump 结构总览 |

用法详见 [`tools/reverse/README.md`](../tools/reverse/README.md)。
