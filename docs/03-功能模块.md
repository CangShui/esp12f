# 03 · 各功能模块实现方式

> 源码： [`firmware/ES12F_Local/`](../firmware/ES12F_Local/)
> 四个文件：`ES12F_Local.ino`（主程序）、`config.h`（配置）、`storage.h`（配置存储）、`pages.h`（网页）

---

## 0. 总览

```
setup()
 ├── hardwareBoot()        复刻原厂上电时序 + 识别配网按钮
 ├── cfgLoad()             从 flash 0xFB000 读 WiFi 配置
 ├── registerRoutes()      注册 80 端口全部路由
 └── 二选一
      ├── startPortal()    热点配网模式（AP + DNS 强制门户）
      └── startStation()   正常联网模式（STA + HTTP 服务）

loop()
 ├── server.handleClient() 处理 HTTP
 ├── actService()          非阻塞推进电源动作状态机
 ├── LED 指示               配网=慢闪；执行动作=常亮；其余=灭
 ├── 配网模式下每 30s 重试已保存的 WiFi
 └── g_rebootAt 到点 → ESP.restart()
```

## 1. 模块一：配网（原厂行为 + 增强）

### 1.1 三种进入方式

| 方式 | 触发条件 | 代码位置 |
|---|---|---|
| **按住配网按钮上电**（原厂行为） | `digitalRead(GPIO4) == LOW` | `hardwareBoot()` |
| 无已保存 WiFi | `!cfgHasWifi()` | `setup()` |
| 联网 20 秒失败 | `startStation()` 超时 | `startStation()` |

```c
// hardwareBoot()
g_forceConfig = (digitalRead(PIN_SENSE2) == LOW);
...
if (digitalRead(PIN_SENSE2) == LOW) g_forceConfig = true;   // 等待期间按下也算

// setup()
if (g_forceConfig || !cfgHasWifi()) startPortal();
else                                startStation();
```

### 1.2 AP 热点 + DNS 强制门户

```c
WiFi.mode(WIFI_AP_STA);                       // AP_STA：既能开热点也能扫描
snprintf(ap, sizeof(ap), "ES12F_%06X", ESP.getChipId());
WiFi.softAP(ap);                              // 无密码，SSID 如 ES12F_849206
dnsServer.start(53, "*", WiFi.softAPIP());    // 所有域名解析到 192.168.4.1
```

任何未知请求都被 302 重定向到配网页，实现"连上热点自动弹配网页"：

```c
static void handleNotFound() {
  if (g_portal) {
    server.sendHeader(F("Location"),
        String("http://") + WiFi.softAPIP().toString() + "/", true);
    server.send(302, F("text/plain"), "");
    return;
  }
  server.send(404, ...);
}
```

### 1.3 配网页与原厂逐字节一致

配网页 HTML 是从原厂固件 flash `0x5015C` 处**逐字节提取**的，直接内嵌在 `pages.h` 里
（`PAGE_CONFIG`）。协议也照旧：

```
POST /?ssid=xxx&password=yyy   →  纯文本 "OK"
GET  /scan                     →  JSON 数组 ["SSID1","SSID2",...]
```

原厂页面里的 JS 判断 `responseText == 'OK'`，所以必须返回纯文本 `OK`。

### 1.4 配网 → 联网的切换

```c
WiFi.softAPdisconnect(true);   // ★ 不能用 WiFi.mode(WIFI_STA)
```

用 `WiFi.mode(WIFI_STA)` 会顺带断掉刚刚建立的 STA 连接；`softAPdisconnect()` 只关热点。

## 2. 模块二：电源控制（核心）

### 2.1 时序（与原厂逐条对齐）

| 动作 | 实现 | 对应原厂地址 |
|---|---|---|
| 开机 | GPIO12 高 500ms → 低 | `0x40203BB2/BBB/BC5` |
| 关机 | GPIO12 高 8000ms → 低 → 静置 2000ms | `0x40203BF1/BFA/C04` |
| 重启 | GPIO5 高 200ms → 低 | `0x40203CAE→CCE` |
| 状态 | `digitalRead(14)`，高 = 已开机 | `0x40203AF6` |

### 2.2 关键设计：非阻塞状态机

**最初版本用 `delay(8000)` 阻塞执行，导致这 8~10 秒内 Web 服务完全无响应**，
页面的状态轮询全部挂死，按钮看起来"卡灰不恢复"。

现在改成状态机，动作在 `loop()` 里按毫秒分步推进：

```c
static uint8_t  g_act = 0;       // 0=空闲 1=开机 2=关机 3=重启
static uint8_t  g_actPhase = 0;
static uint32_t g_actT0 = 0;

static void actService() {
  if (!g_act) return;
  uint32_t el = millis() - g_actT0;

  if (g_act == ACT_ON) {
    if (g_actPhase == 0) { digitalWrite(PIN_PWR, PWR_ACTIVE); g_actPhase = 1; g_actT0 = millis(); }
    else if (g_actPhase == 1 && el >= T_PWR_SHORT) {
      digitalWrite(PIN_PWR, PWR_IDLE);
      actFinish("开机指令已执行");
    }
  } else if (g_act == ACT_OFF) {
    if (g_actPhase == 0) { digitalWrite(PIN_PWR, PWR_ACTIVE); g_actPhase = 1; g_actT0 = millis(); }
    else if (g_actPhase == 1 && el >= T_PWR_LONG)  { digitalWrite(PIN_PWR, PWR_IDLE); g_actPhase = 2; g_actT0 = millis(); }
    else if (g_actPhase == 2 && el >= T_PWR_SETTLE) { actFinish("关机指令已执行"); }
  } else if (g_act == ACT_RST) {
    if (g_actPhase == 0) { digitalWrite(PIN_RST, RST_ACTIVE); g_actPhase = 1; g_actT0 = millis(); }
    else if (g_actPhase == 1 && el >= T_RST_PULSE) { digitalWrite(PIN_RST, RST_IDLE); actFinish("重启指令已执行"); }
  }
}
```

**收益**：动作执行期间 `server.handleClient()` 照常运行，网页能实时显示
「执行中… 关机」，进度条不卡。

### 2.3 并发保护

```c
static void queueAction(uint8_t act, const char *name) {
  if (actBusy()) {                    // 已有动作在跑
    sendJson(409, "{\"ok\":false,\"busy\":true,\"msg\":\"...正在执行中，请稍候\"}");
    return;
  }
  actStart(act);
  sendJson(200, "{\"ok\":true,...}");  // 立即返回，不等待动作完成
}
```

**按钮不置灰**（前端也不禁用），重复点击只会收到 409 + 提示，不会叠加动作。

### 2.4 指令计数

```c
static uint32_t g_cmdCount = 0;    // 每次 actFinish() 自增
```

状态 JSON 里返回 `"cmds"`。用途：**证明刷新网页不会重发命令**——
刷新多少次这个数字都不变。

## 3. 模块三：HTTP 服务与页面

### 3.1 路由表

```c
server.on("/",           HTTP_GET,  handleRoot);      // 配网页 或 控制页
server.on("/",           HTTP_POST, handleSaveWifi);  // 原厂保存方式
server.on("/config",     HTTP_GET,  handleConfigPage);
server.on("/scan",       HTTP_GET,  handleScan);
server.on("/save",       HTTP_POST, handleSaveWifi);
server.on("/reset",      HTTP_GET,  handleClearWifi);
server.on("/api",        HTTP_GET,  handleApi);
server.on("/api/on",     HTTP_GET,  handleApi);
server.on("/api/off",    HTTP_GET,  handleApi);
server.on("/api/restart",HTTP_GET,  handleApi);
server.on("/api/status", HTTP_GET,  handleStatus);
#if OTA_ENABLE
server.on("/update",     HTTP_GET,  handleUpdatePage);
server.on("/update",     HTTP_POST, handleUpdateDone, handleUpdateUpload);
#endif
server.onNotFound(handleNotFound);
```

`/` 同时支持 `?cmd=on` 这种"一键命令"写法：

```c
static void handleRoot() {
  if (server.hasArg("cmd")) { handleApi(); return; }
  sendPage(g_portal ? (PGM_P)PAGE_CONFIG : (PGM_P)PAGE_INDEX);
}
```

### 3.2 响应统一带 `Connection: close`

```c
static void sendPage(PGM_P page) {
  server.sendHeader(F("Cache-Control"), F("no-store"));
  server.sendHeader(F("Connection"), F("close"));   // ★
  server.send_P(200, PSTR("text/html; charset=utf-8"), page);
}
```

**为什么要加**：keep-alive 长连接在设备阻塞时会被拖死，导致浏览器后续请求
一直悬着、页面像"死"了一样。强制短连接后每次都是全新请求。

### 3.3 控制页前端（`PAGE_INDEX`）

三个关键设计：

**① 按钮永不置灰**

```js
/* 按钮永不置灰，只加一个淡色提示 */
['bOn','bOff','bRst'].forEach(function(id){
  var el=document.getElementById(id);
  if(busy) el.classList.add('busy'); else el.classList.remove('busy');
});
```

**② 请求带超时**（避免设备忙时 fetch 永久挂起）

```js
function fetchT(url,ms){
  return new Promise(function(res,rej){
    var ctl=new AbortController();
    var done=false;
    var t=setTimeout(function(){ if(!done){done=true;ctl.abort();rej(new Error('timeout'));} },ms);
    fetch(url,{cache:'no-store',signal:ctl.signal}).then(function(r){
      if(done) return; done=true; clearTimeout(t); res(r);
    }).catch(function(e){ if(done) return; done=true; clearTimeout(t); rej(e); });
  });
}
```

**③ 首次加载不弹提示**

```js
/* 首次加载不弹提示；之后只有「最近指令」真的变了才弹，
   避免刷新页面误以为重发命令 */
if(!first && d.last && d.last!==lastMsg) toast(d.last);
lastMsg=d.last; first=false;
```

自动刷新：`setInterval(refresh, 2000)`（2 秒），另有手动「刷新状态」按钮。

## 4. 模块四：局域网刷机（OTA）

### 4.1 原理（已查证 core 源码）

`Updater::end()` 使用的是 eboot 的 `ACTION_COPY_RAW`：

```c
// core Updater.cpp 第 345-350 行
eboot_command ebcmd;
ebcmd.action = ACTION_COPY_RAW;
ebcmd.args[0] = _startAddress;   // 新固件暂存地址 = 0xFB000 - 镜像大小
ebcmd.args[1] = 0x00000;         // ★ 目标 = flash 0x0
ebcmd.args[2] = _size;
eboot_command_write(&ebcmd);
```

复位后 eboot 把暂存区的新固件**拷回 `0x0`**，再跳到 `0x0+0x1000` 执行。

**关键结论：**

| 结论 | 依据 |
|---|---|
| 掉电不丢 | `eboot_command` 虽存 RTC 内存，但 `ACTION_COPY_RAW` 在第一次复位时就**写回了 flash 0x0** |
| 上传的文件 = 串口刷写的同一个 `.bin` | eboot 从 `args[0]+0x1000` 读 app，而合并镜像的 app 恰在 `0x1000` 偏移 |
| 配置扇区不动 | 暂存地址 = `0xFB000 - roundedSize`，拷贝目标 `0x0`，都不碰 `0xFB000` |
| 空间足够 | 可用 = `0xFB000 - 当前固件对齐大小` = `0xFB000 - 0x52000` ≈ **696KB**，固件约 328KB |

### 4.2 安全限制：源 IP 白名单

```c
static bool isLocalClient() {
  IPAddress ip = server.client().remoteIP();
#if OTA_ALLOW_LOOP
  if (ip[0] == 127) return true;                              // 127.0.0.0/8
#endif
#if OTA_ALLOW_10
  if (ip[0] == 10) return true;                               // 10.0.0.0/8
#endif
#if OTA_ALLOW_172
  if (ip[0] == 172 && ip[1] >= 16 && ip[1] <= 31) return true; // 172.16.0.0/12
#endif
#if OTA_ALLOW_192
  if (ip[0] == 192 && ip[1] == 168) return true;              // 192.168.0.0/16
#endif
  return false;
}
```

**在 `UPLOAD_FILE_START` 阶段就检查**，不通过则直接丢弃数据、不写 flash：

```c
static void handleUpdateUpload() {
  HTTPUpload &up = server.upload();
  if (up.status == UPLOAD_FILE_START) {
    g_otaAllowed = isLocalClient() && otaTokenOk();
    if (!g_otaAllowed) return;                 // 不写 flash
    uint32_t maxSketch = (ESP.getFreeSketchSpace() - 0x1000) & 0xFFFFF000;
    if (!Update.begin(maxSketch, U_FLASH)) Update.printError(Serial);
  } else if (!g_otaAllowed) {
    return;
  } else if (up.status == UPLOAD_FILE_WRITE) {
    if (Update.write(up.buf, up.currentSize) != up.currentSize) Update.printError(Serial);
  } else if (up.status == UPLOAD_FILE_END) {
    Update.end(true);
  }
}
```

可选令牌（`config.h` 里 `OTA_TOKEN` 非空即启用）：

```c
static bool otaTokenOk() {
  if (sizeof(OTA_TOKEN) <= 1) return true;      // 未设置
  return server.arg("token") == F(OTA_TOKEN);
}
```

### 4.3 与"删除远程更新"并不冲突

| | 原厂 | 现在 |
|---|---|---|
| 方向 | 设备**主动去**厂商服务器拉固件 | 浏览器**推**给设备 |
| 目标 | `songguoyun.topwd.top` | 无（设备不发起任何连接） |
| 权限 | 厂商可随时替换你的固件 | 只有局域网私有 IP 能刷 |
| 代码证据 | 有 `ESP8266HTTPUpdate` + URL 字符串 | 无 HTTP 客户端、无域名 |

## 5. 模块五：配置存储

`storage.h` 直接读写 flash `0xFB000`（与原厂同一扇区）：

```c
#define CFG_OFF_SSID   0x000   // 32 字节
#define CFG_OFF_PASS   0x020   // 64 字节
#define CFG_OFF_EXTRA  0x080
#define CFG_SIZE       256
#define CFG_MAGIC      0x32464631   // "1FF2" 小端
```

接口：

```c
void cfgLoad();                                    // 启动时读
void cfgSaveSsidPass(const char *ssid, const char *pass);
void cfgClear();
bool cfgHasWifi();
```

**为什么能读到原厂配置**：Arduino core 的 `eagle.flash.1m.ld` 里
`_EEPROM_start = 0x402fb000`，即 flash `0xFB000`，与原厂自定义配置区完全重合。

if (g_portal) {
